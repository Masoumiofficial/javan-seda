# تغییرات نسخهٔ ۳.۷.۱ — نامک انگلیسی آرشیوها

نسخهٔ کوچک و فقط دربارهٔ **آدرس‌ها**. هیچ فایل قالب، هیچ فیلد و هیچ گزینه‌ای
غیر از نامک پنج تاکسونومی موسیقی عوض نشده است.

## چه چیزی عوض شد

| تاکسونومی | آدرس در ۳.۷.۰ | آدرس در ۳.۷.۱ |
| --- | --- | --- |
| ژانر | `/genre/…` | **`/genre/…`** (بی‌تغییر) |
| حال‌وهوا | `/mood/…` | **`/mood/…`** (بی‌تغییر) |
| ترانه‌سرا | `/tarane-sara/…` | **`/songwriter/…`** |
| آهنگساز | `/ahangsaz/…` | **`/composer/…`** |
| تنظیم | `/tanjim/…` | **`/arranger/…`** |

هر پنج آرشیو حالا نامک انگلیسی دارند و همان قالب مشترک
`inc/tax-listing.php` را می‌خوانند؛ `rest_base` هم همان نامک انگلیسی است، پس
آدرس REST هم یکدست شد: `/wp-json/wp/v2/songwriter` و مانند آن.

**نامک خود ترم‌ها دست نمی‌خورد.** اگر ترمی با نامک فارسی یا لاتین ساخته بودید،
همان می‌ماند؛ فقط پیشوند آرشیو عوض شده.

## بازسازی خودکار پیوند یکتا

اگر قالب از قبل روشن باشد، وردپرس قوانین تازه را خودش نمی‌گیرد. برای همین یک
مهر سبک اضافه شد:

```php
get_option( 'taranehyar_music_rewrite_stamp' );   // فقط یک رشته
```

تابع `tara_music_taxonomies_stamp()` روی `init` (اولویت ۱۳) مهر فعلی را با مهر
ذخیره‌شده مقایسه می‌کند؛ اگر فرق کرد، **یک‌بار** `flush_rewrite_rules( false )`
اجرا می‌شود و مهر ذخیره. پس بعد از آپلود بسته، اولین بازدید کافی است و
لازم نیست دستی «تنظیمات → پیوندهای یکتا → ذخیره» بزنید.

- خاموش‌کردن دستی: `add_filter( 'tara_music_rewrite_stamp', fn() => 'mine' );`
- بررسی: یک آدرس مثل `/songwriter/…` را باز کنید؛ باید آرشیو بیاید نه ۴۰۴.

## بازگشت

بستهٔ `taranehyar-3.7.0.zip` را Overwrite کنید. آرشیوها به همان نامک‌های قبلی
برمی‌گردند و مهر تازه هم یک‌بار دیگر بازسازی می‌کند. هیچ ترم یا رابطه‌ای حذف
نمی‌شود؛ فقط پیشوند آدرس عوض می‌شود.

## آزمون

`tests/run-370.php` سه سنجهٔ تازه گرفت: نامک انگلیسی هر پنج آرشیو، یکسان‌بودن
`rest_base` با نامک، و رفتار مهر (بار اول بازسازی می‌کند، بار دوم نه، با مهر
عوض‌شده دوباره بازسازی می‌کند). جمع سنجه‌ها: **۳۴۶ pass / ۰ fail**.
