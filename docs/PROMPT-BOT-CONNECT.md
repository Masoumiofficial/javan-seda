# پرامتِ کاملِ «وصل‌کردنِ رباتِ تلگرام به سایتِ آهنگ‌بان»

> این فایل خودش یک **پرامت** است: تمامش را کپی کنید و به ایجنت (Codex / Claude Code / Cursor / …) بدهید.
> ایجنت باید بتواند فقط با همین متن، رباتِ `ahangbanbot` را به قالبِ `taranehyar` (سایتِ `ahangban.ir`) وصل، تنظیم و تست کند.
> هر جا عدد یا مسیری نوشته شده، همان مقدارِ واقعیِ کد است — از خودتان عدد نسازید.

---

## ۰) نقشِ تو

تو یک مهندسِ بک‌اند هستی که باید دو چیز را به هم وصل کند:

1. **رباتِ تلگرام** (`github.com/Masoumiofficial/ahangbanbot`، شاخهٔ `main`، نسخهٔ v1.6.2، Python + `python-telegram-bot`)
2. **قالبِ وردپرسی** (`taranehyar` v3.11.0) که RESTِ آماده دارد و پنلِ کاربری‌اش از قبل نوشته شده است.

قراردادِ بین این دو **قبلاً تعریف شده** و تو نباید آن را عوض کنی. کارِ تو «پیاده‌سازیِ همین قرارداد و تحویلِ چک‌لیستِ سبز» است.
اگر چیزی در ربات با قرارداد نمی‌خواند، آن را در سمتِ ربات اصلاح کن؛ **سمتِ قالب را بدونِ دلیل تغییر نده**.

---

## ۱) نقشهٔ دو طرف

## ۲) قراردادِ قطعی (تغییر نده)

### ۲-۱) احرازِ هویت
- همهٔ مسیرها جز `/health` نیاز به توکن دارند.
- توکن فقط از این دو جا خوانده می‌شود (به همین ترتیب):
  1. تنظیماتِ قالب → «حساب کاربری و ورود» → **توکنِ ربات** (گزینهٔ `tg_token`)
  2. آپشنِ وردپرس `ahangban_connector_token` (افزونهٔ `ahangban-connector`)
- قالب: ۶۴ کاراکترِ hex، با `hash_equals` مقایسه می‌شود. اگر مقدار hex-64 نباشد، **انگار تنظیم نشده**.
- هدرها (هر سه پذیرفته می‌شود): `Authorization: Bearer <token>` · `X-Tara-Token: <token>` · `X-Ahangban-Token: <token>`
- خطاها: `401` بدونِ توکن · `503` توکن تنظیم نشده · `403` توکنِ نامعتبر · `429` زیاد بودنِ درخواست.
- محدودیتِ نرخ: ۱۲۰ درخواست در دقیقه به‌ازای هر IP، ۸۰ در دقیقه به‌ازای هر `telegram_id`.

### ۲-۲) مسیرها (پیشوندِ `https://ahangban.ir/wp-json/ahangban/v1`)

| متد | مسیر | پارامترها | خروجیِ موفق |
|---|---|---|---|
| GET | `/health` | — | `{ ok:true, site, version }` — **بدونِ توکن** |
| POST | `/link` | `code`, `telegram_id`, `username`, `first_name` | `{ ok:true, user:{…} }` |
| POST | `/unlink` | `telegram_id` | `{ ok:true }` |
| GET | `/me` | `telegram_id` | خلاصهٔ کاربر (پایین) |
| GET | `/follows` | `telegram_id` | `{ follows:[…] }` |
| POST | `/follow` | `telegram_id`, `artist` (شناسهٔ ترم)، `on` (`1`/`0`) | `{ ok:true, following, count }` |
| GET | `/feed` | `telegram_id`, `since`, `limit` | آهنگ‌های تازهٔ خواننده‌های دنبال‌شده |
| POST | `/like` | `telegram_id`, `post`, `on` | `{ ok:true, liked, count }` |
| GET | `/playlists` | `telegram_id` | فهرستِ پلی‌لیست‌ها |
| POST | `/playlist` | `telegram_id`, `action`(`create`/`add`/`remove`/`delete`), `key`, `name`, `post` | وضعیتِ پلی‌لیست |
| GET | `/notifications` | `telegram_id` | پیام‌های سایت برای کاربر |
| POST | `/read` | `telegram_id` | `{ ok:true }` |

### ۲-۳) شکلِ خلاصهٔ کاربر (`/me` و داخلِ `/link`)
```json
{
  "id": 12, "name": "شنونده", "url": "https://ahangban.ir/account/",
  "avatar": "https://ahangban.ir/…/avatar.jpg",
  "counts": { "likes": 4, "playlists": 2, "follows": 7, "history": 30, "unread": 0, "tracks": 11 },
  "follows": [ { "id": 33, "name": "محسن یگانه", "url": "…", "count": 142 } ],
  "linked": true
}
```

### ۲-۴) جریانِ اتصال (سایت → ربات)
1. کاربر در سایت وارد می‌شود و در تبِ «تلگرام» دکمهٔ **«ساختِ کدِ اتصال»** را می‌زند.
2. سایت کدی ۸ کاراکتری از الفبای `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` می‌سازد و در transient با کلیدِ `tara_link_<CODE>` و عمرِ `tg_code_ttl` (پیش‌فرض ۶۰۰ ثانیه) نگه می‌دارد.
3. کاربر همان کد را **به‌صورتِ متن** در چتِ ربات می‌فرستد (⚠️ نه در پارامترِ `start`).
4. ربات باید کد را در پیامِ آزاد تشخیص دهد، سپس:
   ```
   POST /link  { "code": "<CODE>", "telegram_id": <id>, "username": "…", "first_name": "…" }
   ```
5. اگر `200` گرفت، به کاربر بگوید «حساب وصل شد» و خلاصهٔ `/me` را نشان دهد.
   اگر `400` گرفت، پیامِ خودِ سرور را نشان دهد (کدِ نادرست/منقضی).

> **مهم:** قبل از شما، سایت یک لینکِ `?start=tara_<CODE>` هم می‌ساخت؛ **دیگر از آن استفاده نمی‌شود** و در رابطِ کاربری هم نمایش داده نمی‌شود. مسیرِ رسمی همان «فرستادنِ کد به‌شکلِ متن» است.

### ۲-۵) دیپ‌لینکِ آهنگ (ربات ← سایت)
- سایت دکمهٔ «مشاهده در ربات تلگرام» را با این آدرس می‌سازد:
  `https://t.me/<bot>?start=song_<post_id>`
- ربات باید در `/start` آرگومان را با الگوی `song_([1-9][0-9]*)` بخواند و همان آهنگ را نشان دهد.
- این بخش در `bot/handlers/start.py` از قبل پیاده شده؛ **فقط تأییدش کن**.

## ۳) کارهایی که باید انجام بدهی (به ترتیب)

### گامِ ۱ — توکن
1. یک رشتهٔ `openssl rand -hex 32` بساز.
2. در وردپرس: **تنظیماتِ قالب → حساب کاربری و ورود → توکنِ ربات** = همان مقدار.
3. در سرورِ ربات، محیط:
   ```
   AHANGBAN_API_BASE=https://ahangban.ir/wp-json/ahangban/v1
   AHANGBAN_API_TOKEN=<همان ۶۴ کاراکتر>
   TELEGRAM_BOT_TOKEN=<توکنِ BotFather>
   ADMIN_IDS=<شناسه‌های عددیِ ادمین، با کاما>
   ```
   (نامِ دقیقِ متغیرها را در `bot/config.py` تأیید کن و اگر لازم بود آن را به همین نام‌ها وصل کن.)

### گامِ ۲ — اتصالِ کد در ربات
- یک هندلر برای پیامِ متنی بساز که با regex `^[A-HJ-NP-Z2-9]{8}$` کد را تشخیص دهد.
- همان‌جا `POST /link` را صدا بزن (با هدرِ Bearer و timeout 15s).
- خروجی را با پیام‌های فارسیِ روشن به کاربر نشان بده:
  - موفق: «✅ حسابِ سایت به تلگرام وصل شد. از این به بعد هرجا آهنگ ذخیره کنی، این‌جا هم هست.»
  - کدِ غلط: «این کد معتبر نیست یا منقضی شده. از سایت یک کدِ تازه بگیر.»
  - خطای شبکه: «الان نمی‌توانم به سایت وصل شوم؛ چند لحظه بعد دوباره بفرست.»
- اگر همان `telegram_id` قبلاً وصل است، **دوباره `/link` نزن**؛ ابتدا `GET /me` بگیر و بگو «قبلاً وصل است».

### گامِ ۳ — دستورهای پیشنهادی ربات
| دستور | کار | مسیر |
|---|---|---|
| `/start` | خوش‌آمد + (اگر `song_<id>` بود، همان آهنگ) | `song` handler |
| `/me` | خلاصهٔ حسابِ سایت | `GET /me` |
| `/saved` | علاقه‌مندی‌ها | `GET /me` → counts + صفحه‌بندیِ آهنگ‌های ذخیره‌شده از سایت |
| `/follows` | خواننده‌های دنبال‌شده | `GET /follows` |
| `/latest` | تازه‌های دنبال‌شده‌ها | `GET /feed` |
| `/unlink` | قطعِ اتصال | `POST /unlink` |
| `/help` | راهنما | — |

### گامِ ۴ — رفتارِ خطا (اجباری)
- `401/403` ⇒ «توکنِ ربات در سایت درست تنظیم نشده» را **فقط در لاگ** بنویس و به کاربر پیامِ عمومی بده.
- `429` ⇒ «کمی آرام‌تر! چند ثانیه بعد دوباره امتحان کن.»
- `404` با کدِ `tara_unlinked` ⇒ «اول حسابِ سایت را وصل کن؛ از پنلِ سایت کدِ اتصال بگیر.»
- هرگز `telegram_id` کاربر را در پیامِ عمومی چاپ نکن.

### گامِ ۵ — کش
- `api_client.py` کشِ داخلی با `CACHE_TTL=300` دارد؛ بعد از هر `POST` که وضعیت را عوض می‌کند (`/link`, `/unlink`, `/like`, `/follow`, `/playlist`) کشِ همان `telegram_id` را **پاک کن**، وگرنه کاربر تا ۵ دقیقه دادهٔ کهنه می‌بیند.

## ۴) تستِ پذیرش (باید همه سبز شوند)

با `curl` (مقدارها را جایگزین کن):

```bash
BASE=https://ahangban.ir/wp-json/ahangban/v1
TOK=<64-hex>
TG=<telegram_id آزمون>

# ۱) سلامت — بدونِ توکن
curl -s $BASE/health

# ۲) بدونِ توکن باید 401 بدهد
curl -s -o /dev/null -w '%{http_code}\n' $BASE/me?telegram_id=$TG

# ۳) با توکنِ غلط باید 403 بدهد
curl -s -o /dev/null -w '%{http_code}\n' -H 'Authorization: Bearer bad' "$BASE/me?telegram_id=$TG"

# ۴) اتصالِ کد (کد را از پنلِ سایت بگیر)
curl -s -X POST $BASE/link -H "Authorization: Bearer $TOK" \
  -d "code=ABCD2345&telegram_id=$TG&username=test&first_name=Test"

# ۵) خلاصهٔ کاربر
curl -s -H "Authorization: Bearer $TOK" "$BASE/me?telegram_id=$TG"

# ۶) قطعِ اتصال
curl -s -X POST $BASE/unlink -H "Authorization: Bearer $TOK" -d "telegram_id=$TG"
```

چک‌لیستِ دستی (در تلگرام):
- [ ] `/start` خوش‌آمد می‌دهد.
- [ ] `?start=song_<id>` همان آهنگ را باز می‌کند.
- [ ] فرستادنِ کدِ درست ⇒ «وصل شد» + نامِ کاربر از سایت.
- [ ] فرستادنِ کدِ غلط ⇒ پیامِ خطای روشن.
- [ ] فرستادنِ کدِ منقضی (بعد از `tg_code_ttl`) ⇒ پیامِ «کدِ تازه بگیر».
- [ ] `/me` بعد از اتصال، شمارنده‌ها را نشان می‌دهد.
- [ ] `/unlink` اتصال را قطع می‌کند و بعدش `/me` می‌گوید وصل نیست.
- [ ] در سایت، تبِ «تلگرام» بعد از اتصال «تلگرام به حساب شما وصل است» و نام‌کاربریِ `@…` را نشان می‌دهد.
- [ ] با دو کاربرِ هم‌زمان، داده‌ها قاطی نمی‌شوند.
- [ ] لاگِ ربات هیچ توکنی را چاپ نمی‌کند.

---

## ۵) نکاتِ امنیتی (غیرقابلِ مذاکره)
- توکن را **در کدِ ربات هارد‌کد نکن**؛ فقط از محیط بخوان.
- توکن را در لاگ، پیامِ خطا و پاسخِ API چاپ نکن.
- `telegram_id` همیشه عددِ صحیحِ مثبت باشد؛ قبل از ارسال اعتبارسنجی کن.
- برای هر درخواست `User-Agent: AhangBanBot/1.0` بفرست (سمتِ سایت لاگ را بهتر می‌فهمد).
- HTTPS اجباری است؛ اگر سایت روی HTTP بود، اتصال را نساز و به مدیر بگو.

## ۶) تعریفِ «تمام‌شده»
1. همهٔ بندهای چک‌لیستِ بخش ۴ سبز.
2. `curl` های بخش ۴ خروجیِ درست می‌دهند.
3. هیچ تغییری در قالبِ وردپرس لازم نشده باشد (اگر لازم شد، فهرستش را دقیق گزارش کن).
4. یک فایلِ `docs/BOT-SETUP-RESULT.md` بساز: نسخهٔ ربات، نسخهٔ قالب، تاریخِ تست، خروجیِ `/health`، و اینکه هر بند چطور تأیید شد.
