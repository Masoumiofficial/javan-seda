# ترانه یار ۳.۷.۱۰ — دور ۶۸

بازبینی سایتِ زندهٔ `ahangban.ir` روی گوشی (اسکرین‌شات کاربر، Galaxy S23،
`360×780` CSS) و رفع ایرادهای دیده‌شده.

---

## ۱) اسلایدر صفحهٔ اصلی — کاور دیگر بریده نمی‌شود

**چیزی که در اسکرین‌شات دیده می‌شد:** بنر «MEGA MIX» از دو طرف بریده بود
(«EGA MIX»، «UID RAZAVI») و بخشی از متنِ اثر بیرون از کادر افتاده بود.

**علت:** تک‌تصویر با `object-fit: cover`. بنرهای پهن (نسبت ۲:۱ یا بیشتر) در
کادرِ ۱۶:۹ به‌طور خودکار از دو طرف بریده می‌شوند.

**رفع:** هر اسلاید حالا **دو لایهٔ تصویر** دارد:

| لایه | کار | استایل |
|---|---|---|
| `.ty-hero-slide__bg` | پس‌زمینهٔ تمام‌قاب تا هیچ ناحیهٔ خالی/سفیدی نماند | `object-fit: cover` + `blur(18px)` + `brightness(.55)` |
| `.ty-hero-slide__img` | خودِ کاور، کامل و بدون برش | `object-fit: contain` |

- هر دو `<img>` **همان آدرس** را دارند ⇒ درخواست شبکه اضافه نمی‌شود (کش).
- لایهٔ پشت `aria-hidden="true"` و `alt` خالی دارد تا صفحه‌خوان دوبار نخواند.
- `prefers-reduced-motion` بلور را برمی‌دارد و فقط تیره می‌کند (گوشی ضعیف).

**نسبت گوشی:** `16 / 9` (پیش‌تر `5 / 4` بود). کوتاه‌تر، هم‌اندازهٔ بنرهای سایت
و مطابق نسبت طبیعی بیشتر کاورها.

نشانگرها در گوشی ریزتر شدند (`18px` با نقطهٔ `8px`) تا روی کاور شلوغی نسازند.

## ۲) نوار چسبان گوشی — از شبکه به فلکس

**چیزی که در اسکرین‌شات دیده می‌شد:** ردیف پایین نوار، سه دکمهٔ
قبلی/پخش/بعدی را همه سمت راست جمع کرده بود و نیمهٔ چپ خالی مانده بود؛ نوار
هم به‌خاطر ردیف‌های اضافه و `env(safe-area-inset-bottom)` حدود ۱۵۸px بلند شده
بود.

**رفع:**

```
ردیف ۱:  [کاور ۴۰]  نام آهنگ / هنرمند      [فهرست پخش] [بستن]
ردیف ۲:  [قبلی] ................ [پخش ۴۶] ................ [بعدی]
```

- `display: flex` + `flex-wrap` + شکست‌خطِ نامرئی (`::after` با `flex: 0 0 100%`)
- ترتیب صریح با `order` (اطلاعات ۱–۴، شکست ۵، ترابری ۶–۸)
- `justify-content: space-between` ⇒ سه دکمهٔ ترابری تمام عرض را پر می‌کنند
- کنترل صدا در گوشی همچنان پنهان است (درخواست قبلی) و «فهرست پخش» کنار «بستن»
- ارتفاع بدنهٔ نوار: ~۱۵۸px → **~۱۰۰px**
- `body.has-tara-dock` و دکمهٔ «بالا» با همان ارتفاع هم‌خوان شدند
  (`calc(112px + safe-area)` / `calc(122px + safe-area)`)

## ۳) کارت پلیر در گوشی — بازچینش کامل

| ایراد | رفع |
|---|---|
| دو دکمهٔ ابزار وسطِ کارت شناور بودند | `.ty-player__labels { flex: 1 1 auto }` ⇒ ابزارها به لبه می‌چسبند |
| فاصلهٔ خالی بزرگ بین نام خواننده و دکمهٔ پخش | شبکهٔ صریح `"art head" / "transport transport"` با `gap: 8px 12px` |
| ردیف زمان/نوار پیشرفت به خط سوم می‌رفت و از کادر می‌زد | ترتیب صریح: دکمه‌ها (۱–۳)، زمان (۴)، بی‌صدا (۵)، نوار (۶، تمام‌عرض) |
| نام آهنگ با «…» در یک خط بریده می‌شد | حداکثر **دو خط** با `-webkit-line-clamp: 2` |
| دکمهٔ دوربین روی کاور ۷۶px بزرگ بود | ۲۸px → **۲۲px** در گوشی |
| اسلایدر صدا در کارت | در گوشی پنهان (دکمهٔ بی‌صدا می‌ماند) |

## ۴) برچسب «mp3» بالای پلیر

مقدار فیلد «نوع اثر» در بعضی نوشته‌ها نام فرمت است و بالای پلیر مثل کد خام
دیده می‌شد (`mp3`). حالا:

```php
$tara_type_label = $taranehyar_type;
if ( preg_match( '/^(mp3|mp4|m4a|wav|flac|ogg|3gp|webm|mkv|aac)$/i', $taranehyar_type ) ) {
	$tara_type_label = 'پخش آنلاین';
}
```

تیتر بخش دانلود **عمداً** همان مقدار خام را نگه می‌دارد («دانلود mp3 …») چون
هدف جست‌وجوی کاربر است.

## ۵) تنظیمات — پشتیبان و برچسب خنثی

- قاعدهٔ CSS پشتیبان برای آیتم‌های فهرستی:
  `#option-tree-settings-api.tara-tabs-ready .option-tree-setting:not(.tara-li-open) > .option-tree-setting-body { display: none; }`
  ⇒ حتی اگر اسکریپت دیر برسد یا MutationObserver خطا بدهد، باز/بستن با کلاس
  کار می‌کند.
- آیتمی که مدیر برایش عنوان ننوشته، به‌جای سرتیتر خالی «مورد بدون عنوان»
  نشان می‌دهد.
