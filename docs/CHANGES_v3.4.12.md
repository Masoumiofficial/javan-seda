# 3.4.12 — علتِ واقعیِ «خطای مهم در این وب‌سایت» پیدا و ریشه‌کن شد

## پس‌منظر (چه فکری می‌کردیم و چرا نشد)
از دور 3.4.9 سایت با صفحۀ «خطای مهم» باز می‌شد. سه دور روی لایۀ «هنرمند/فیلدهای
ترم» تمرکز کردیم: حائلِ `try/catch` (3.4.10)، حذف `mbstring`، بی‌خطرسازی
`get_terms`/`update_postmeta_cache`/فیلتر ACF، و ناظرِ fatal (3.4.11). هیچ‌کدام
خطا را رفع نکرد — چون خطا هیچ‌وقت در کدِ ما نبود.

## علتِ قطعی
`javanseda/functions.php` و `javanseda/RTL_License_41d6c5f704e3a746.php` فایل‌های
**رمزگذاری‌شدۀ ionCube** هستند (لایسنسِ قالبِ فروختۀ rtl-theme.com). سرآمدشان این است:

    <?php //ICB0 72:0 74:8258 81:fd4a
    // Encrypted by : www.Rtl-Theme.com
    if ( extension_loaded( 'ionCube Loader' ) ) {
        die( 'The file ' . __FILE__ . " is corrupted.\n" );
    }
    … «ionCube Loader for PHP needs to be installed» … exit( 199 );

یعنی اگر لودرِ ionCube فعال باشد **و** فایل با چیزی که لودر انتظار دارد همخوان
نداشت، همان سطرِ `die()` اجرا می‌شود و پیش از هر چیزِ دیگری سایت می‌میرد. پیامش
دقیقاً همین است که کاربر دید:

    The file /home/etehadya/domains/ahangban.ir/public_html/wp-content/themes/javanseda/functions.php is corrupted.

ما در همهٔ بسته‌های «قالب کامل» (3.4.1 تا 3.4.11) `functions.php` را هم گذاشته
بودیم — کپیِ داخل مخزن. نسخۀ روی سرور با آن کپی مو‌به‌مو یکی نیست (چون لودر/لایسنس
روی سرور فایل را عوض کرده، یا فایلِ آپلودشده به گیت‌هاب از نسخۀ دیگری آمده بود).
نتیجه: **هر نصبِ «قالب کامل» = مرگِ سایت**؛ و وقتی کاربر به 3.4.8 برمی‌گشت،
`functions.php` سالم برمی‌گشت و سایت (یا کشِ آن) بالا می‌آمد. صفحۀ اصلی کش‌شده بود،
پس «سایت بالا آمد» و فقط پیشخوان (که کش نمی‌شود) خطا می‌داد — همین گمراه‌کننده بود.

تأییدِ زنده: `https://ahangban.ir/wp-json/` ( درخواستِ کش‌نشده ) همان یک سطرِ
`corrupted` را برمی‌گرداند، درحالی‌که `style.css` روی سرور `3.4.11` است.

## رفع (۴ کار)
1. **`tools/package.py`**: سازندۀ بسته‌های انتشار. هر فایلی که در ۱۲۰ بایت اولش
   `ICB0` داشته باشد از *همۀ* بسته‌ها بیرون نگه داشته می‌شود؛ اگر فایلِ لایسنسی
   در بسته بماند، اسکریپت با خطا می‌ایستد. بسته‌های 3.4.12:
   - `javanseda-v3.4.12-theme.zip` — ۱۲۱ فایل (همان ۱۲۲ فایلِ همیشگی **منهای**
     `functions.php` و `RTL_License_41d6c5f704e3a746.php`)
   - `drop-in-v3.4.12.zip` — `style.css` + `inc/ab-sidebars.php` + `README.txt`
   - `rollback-v3.4.12.zip` — نسخۀ 3.4.11 همان دو فایل + راهنما
2. **`.gitattributes`**: دو فایلِ لایسنس `binary` علامت خوردند تا هیچ `checkout`
   یا همسان‌سازیِ پایانِ خطوطی (CRLF/LF) هرگز به آن‌ها دست نزند — یک بایت اختلاف
   کافی است تا لودر «corrupted» بگوید.
3. **برجکِ عیب‌یابی** (`tools/diag/javan-seda-check.php`): حالا اندازه، `ICB0 ✓/✗`
   و `sha256` همان دو فایل را *پیش از* بالا آوردنِ وردپرس چاپ می‌کند؛ پس حتی وقتی
   کل سایت مرده است، با یک درخواستِ HTTP معلوم می‌شود فایلِ روی سرور کپیِ مخزن است
   یا نسخۀ خودِ سرور. مقادیر کپیِ مخزن:
   - `functions.php` — 95,498 B · `sha256 d99663ca6df0b6d8e1f8990a8e9cbfd96f83443b74095b918a610b35e194f21b`
   - `RTL_License_41d6c5f704e3a746.php` — 64,615 B · `sha256 8e4e2975b4c9df8896576aa0d13548f1d788bc7a70d52cb64f4bf41a76091f9a`
4. **راهنمای بازیابی** برای کاربر در `docs/dropin-README-v3.4.12.txt` (برگرداندنِ
   `functions.php` از بکاپِ هاست/پکیج اورجینال، و اینکه چرا نباید دستش زد).

## چیزهایی که از دورهای قبل سالم ماند و لازم بود
- حائلِ `javan_seda_safe()` و ناظرِ `javan_seda_fatal_watch()` (3.4.10/3.4.11) —
  این‌ها هنوز ارزشمندند: از این پس یک خطا در لایۀ «هنرمند» فقط همان بلوک را حذف
  می‌کند و در `error_log` + `wp-content/javan-seda-error.log` نوشته می‌شود.
- رفعِ رقم‌های فارسی (`javan_seda_fa_digits` → `strtr` با کاراکتر واقعی) ۳.۴.۱۱.
- کلیدهای `JAVANSEDA_TERM_FIELDS` و `JAVANSEDA_ARTIST_ACF_RULES`.
