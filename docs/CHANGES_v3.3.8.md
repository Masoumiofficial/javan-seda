## الف۱) فونت woff2 — بزرگ‌ترین برندهٔ سرعت

**علت ریشه‌ای:** `@font-face`ها فقط `format('woff')` داشتند و در `fonts/` هیچ فایل
woff2 وجود نداشت؛ همۀ مرورگرهای امروزی woff2 می‌فهمند و ۲۰ تا ۳۰ درصد کم‌حجم‌تر است.
`inc/ab-perf.php` هم که لایۀ `@font-face` تزریقی و `preload` را می‌سازد، همان `woff` را
preload می‌کرد ⇒ مرورگر مجبور بود نسخهٔ بزرگ را دانلود کند.

**کاری که شد:**
* پنج فایل woff2 با `fontTools` ساخته و به `javanseda/fonts/` اضافه شد (woff‌های اصلی
  هم سر جایشان ماندند تا fallback امن بماند):

  | فایل | woff | woff2 |
  |------|------|-------|
  | `vazir-fd` (متن) | 45,540 | 35,276 |
  | `vazir-bold-fd` | 48,256 | 37,624 |
  | `vazir-medium-fd` | 47,948 | 37,344 |
  | `vazir-light-fd` | 51,944 | 41,432 |
  | `icofont` (آیکن‌ها) | 104,392 | 86,416 |
  | **مجموع** | **298,080** | **238,092** (−۶۰KB ≈ −۲۰٪) |

  (این فایل‌ها از قبل زیرمجموعه‌سازی شده‌اند؛ برای همین سود کمتر از حالت معمولیِ ۴۰٪ است.)
* `style.css`: هر سه `@font-face` حالا `src` دومی دارد → `woff2 , woff`.
* `css/icofont.min.css`: همان کار روی تک‌قاعدهٔ IcoFont (این فایل بعد از استایل‌های دیگر
  می‌آید، پس اگر دست‌نخورده می‌ماند نسخهٔ `woff` برنده می‌شد).
* `inc/ab-perf.php`:
  * `preload` هوشمند شد: برای هر فونت **اول نسخهٔ woff2 را اگر روی هاست بود** preload
    می‌کند، وگرنه woff؛ `type` هم درست ستانده می‌شود (`font/woff2`). یعنی اگر فایل
    woff2 را آپلود نکنید، هیچ چیز نمی‌شکند.
  * پنج `@font-face` تزریقی هم `woff2 , woff` شدند.

**چطور ببینید کار کرده:** DevTools → Network → فیلتر Font؛ باید `vazir-fd.woff2` با
نوع `font/woff2` و اندازهٔ ≈35KB ببینید (نه 45KB).

## الف۲) `ab-mobile-probe.php` — دو سوراخ بسته شد

**علت ریشه‌ای (بدتر از چیزی که در گزارش قبلی نوشتم):**
1. حالت `?self=1` فقط `k=x` را رد می‌کرد؛ یعنی **هر بازدیدکننده‌ای** با
   `/ab-mobile-probe.php?self=1` سورس کامل کاوشگر را دانلود می‌کرد (بدون لاگین، بدون کلید).
2. اکشن‌های `?dl=1` (دانلود فایل‌های ذخیره‌شده)، `?rm=1` (پاک‌کردنشان) و `?save=1`
   (نوشتن روی دیسک) **پیش از** گیت `current_user_can('manage_options')` بودند.

**کاری که شد:** یک بلوک گیت درست بعد از تعریف `$abp_k` اضافه شد؛ این سه اکشن حالا
`?k=AHANGBAN-PROBE-306` (کلید خطِ `$ABP_TOKEN` خودِ فایل) را می‌خواهند وگرنه `403`
می‌گیرند. `?self=1` هم همان کلید را می‌خواهد. روتین عادی کاوشگر (گزارش بدون اکشن)
دقیقاً مثل قبل فقط با لاگین مدیر کار می‌کند.

> توصیهٔ جدی در چک‌لیست: بعد از تمام‌شدن کارِ موبایل، این فایل را از ریشهٔ هاست
> **حذف** کنید. هیچ کاوشگری نباید برای همیشه روی سرور بماند.

## الف۳) `wp_body_open()` + «پرش به محتوای اصلی»

**علت:** `header.php` دو بار `<body>` چاپ می‌کرد (حالت شب/روز) و هیچ‌وقت
`wp_body_open()` صدا نمی‌زد؛ پلاگین‌های دسترسی‌پذیری/ردیابی و لینک پرش هیچ‌وقت
درج نمی‌شدند. لینک پرش هم نبود، پس کاربر کیبورد مجبور بود از میان تمام آیتم‌های منو
Tab کند.

**کاری که شد:** در `header.php` بعد از بسته‌شدن `if/else` بدنه:

```php
<?php if ( function_exists( 'wp_body_open' ) ) { wp_body_open(); } ?>
<?php if ( ! defined( 'JAVANSEDA_SKIP_LINK' ) || JAVANSEDA_SKIP_LINK ) { ?>
<a class="ab-skip-link" href="#centers_box">پرش به محتوای اصلی</a>
<?php } ?>
```

* لنگر `#centers_box` در همۀ تمپلیت‌های اصلی (home/index/single/page/search/category/tag/404) وجود دارد ⇒ لینک مرده نیست.
* قاعدۀ CSS در بلوک ۳۲ `style.css`: خارج از صفحه با `transform` مخفی، فقط روی `:focus`
  ظاهر می‌شود؛ `z-index:99998` عمداً زیر `mkp` (99999) است تا روی منوی کشویی نیفتد.
* `title-tag` support **عمداً افزوده نشد**: لایۀ `inc/ab-seo.php` عنوان را خودش
  می‌سازد و اضافه‌کردن support باعث دوباره‌سازی/تعارض عنوان می‌شد.
* در عوض `add_theme_support( 'html5', array( 'search-form', 'gallery', 'caption', 'style', 'script' ) )`
  به `myfunctions.php` اضافه شد (مارکاپ استاندارد، حذف `type` از استایل/اسکریپت‌ها).

## ب۱) id تکراری پلیر (DOM غیرمعتبر → کنترل بی‌حرکت)

**علت ریشه‌ای:** `single.php` برای «تک‌آهنگ» و «آلبوم» دو بلوک
`<div class="music_box_player">` می‌ساخت که هر دو دقیقاً `id="audio"` و
`id="volume-bar"` داشتند (`inc/tarlanweb_player.php` هم همین دو id را روی هوم دارد).
`js/scripts.js` هم عمداً تک‌نمونگی است:

```js
nowPlaying = document.getElementById('audio');   // فقط اولین #audio
$('#volume-bar')                                 // فقط اولین نوار صدا
```

نتیجه: در صفحۀ آهنگِ آلبوم‌دار، ردیف کنترل پلیر دوم چاپ می‌شد ولی هیچ‌وقت به
چیزی وصل نبود (کلیک/درگ بی‌اثر) و HTML صفحه دو id تکراری داشت (اعتبارسنج W3C خطا،
اسکریپت‌های افزونه‌ها هم روی اولی می‌افتند).

**کاری که شد (بدون بازنویسی JS):**
* تابع `javan_seda_player_uid()` در `myfunctions.php` (یک شمارندۀ ساده در هر رندر).
* هر بلوک پلیر خصیصه می‌گیرد: `data-ab-player="1|2|3"`، و idها یکتا می‌شوند:
  پلیر اول همان `audio` / `volume-bar` **می‌ماند** (پس JS قالب دست‌نخورده و بدون ریسک
  کار می‌کند)، دومی می‌شود `audio-2` / `volume-bar-2`.
* سه قاعدۀ CSS در بلوک ۳۲: در `[data-ab-player="2"]` فقط **ردیف کنترل مرده** پنهان
  می‌شود؛ `.play-list` (دکمه‌های دانلود هر ردیف آلبوم) سرِ جایش می‌ماند و کارت
  کوتاه‌تر/جمع‌وجورتر می‌شود. قاعده عمداً فقط برای شمارهٔ ۲ نوشته شد تا «نوار پخش
  هوم/فوتر» (=شمارۀ ۱) هرگز بی‌دلیل بی‌کار نشود.

> بازنویسی `js/scripts.js` برای چندنمونگی انجام **نشد**؛ همان‌طور که در دورهای قبل
> گفته شد، کل فایل بر پایهٔ `getElementById`/`querySelector` سراسری است و تغییرش
> ریسک بالایی دارد. اگر روزی خواستید، فقط همان سه خط CSS را حذف کنید.

## ب۲) `srcset` کاورها (کارت‌ها روی موبایل شارپ)

**علت:** کارت‌ها `thumb2` = ۱۹۰×۱۹۰ crop می‌ساختند؛ روی نمایشگرهای DPR2 (همۀ
موبایل‌ها) همین ۱۹۰ پیکسل کشیده می‌شود ⇒ تصویر نرم.

**کاری که شد:** `add_image_size( 'thumb2x', 380, 380, true )` در `myfunctions.php` و
در `inc/songs_post.php` خروجی به `the_post_thumbnail( array( 'thumb2', 'thumb2x' ), … )`
تغییر کرد؛ وردپرس خودش `srcset` + `sizes` را می‌سازد و مرورگر انتخاب می‌کند.

⚠️ **نکتۀ اجرایی:** این تغییر تا وقتی که سایز جدید روی هاست ساخته نشده باشد سودی ندارد —
یک‌بار `wp media regenerate images` (یا افزونۀ Regenerate Thumbnails) اجرا کنید. اگر
اجرا نکنید هم هیچ چیز خراب نمی‌شود: دقیقاً مثل امروز می‌ماند.

## ب۴) کوئری‌های ریل‌های خانۀ سایت

**کاری که شد** روی سه کوئری سفارشی (`home.php` ریل بلوک `hty`،
`inc/mostviews_posts.php` پربازدیدها، `inc/tarlanweb_player.php` پلیر هوم):

* `'no_found_rows' => true` → حذف `SQL_CALC_FOUND_ROWS` (یک COUNT کامل روی `wp_posts`
  که برای ریلِ بدون صفحه‌بندی دور ریخته می‌شد).
* `'ignore_sticky_posts' => true` → پست چسبان دیگر ترتیب ریل را به‌هم نمی‌ریزد.
* `'update_post_term_cache' => false` فقط جایی که برچسب/دسته لازم نیست.
  `update_post_meta_cache` عمداً **true** ماند؛ اگر خاموشش کنید ACF/متا برای هر پست
  یک کوئری جدا می‌زند و نتیجه بدتر می‌شود.
* نه‌تنها ترنزینت روی فهرست ID اضافه **نشد**، بلکه `wp_reset_query()` (که
  `rewind_posts()` هم انجام می‌دهد و پلندر لوپ اصلی را به اول برمی‌گرداند) در ۹ نقطه
  به `wp_reset_postdata()` تبدیل شد — در ویجت‌های سایدبار این یک باگ پنهان واقعی بود.

> چرا ترنزینت نه؟ چون ریل‌های این قالب «پربازدیدترین ۳۰ روز» و «VIP امروز» هستند و
> کش‌کردنشان یعنی محتوای بیات روی صفحهٔ اول. اول همین حذف COUNT را امتحان کنید؛ اگر
> هنوز سنگین بود، ترنزینت را در دور بعد اضافه می‌کنم (یک بلوک جدا، خاموش‌شدنی).

## ب۵) escape روی خروجی‌های خام

گزارش قبلی ۴۲ مورد `echo ot_get_option(...) / echo get_field(...)` را شمرد. در این
نسخه ۲۶ مورد درست شد — همۀ آن‌هایی که **متن یا URL** بودند:

| فایل | تعداد | نوع |
|------|-------|-----|
| `inc/mobiles_header.php` | ۱۳ | `esc_url` روی لوگو/لینک‌های شبکه، `esc_attr` روی alt، `esc_url( home_url() )` جای `bloginfo('url')` (۳ مورد) |
| `header.php` | ۸ | favicon/apple-touch/logo، `head_h1` → `esc_html`، `bloginfo('url')` ×۳ |
| `inc/artist_slider.php` | ۵ | عنوان بلوک، لینک هنرمند، src/alt تصویر |
| `tag.php` | ۵ | لینک‌های اجتماعی ترم |
| `inc/mostviews_posts.php` | ۱ | عنوان ریل |
| `home.php` | ۱ | عنوان ریل (`$artise['title']`) |

**دست‌نخورده ماند (عمداً):** `single.php:5` و `single.php:310` و `inc/artist_slider.php:4-6`
از نوع `echo ot_get_option('ads_bt' | 'adsjs_bt' | 'ads_sg' | 'adsjs_sg')` — این‌ها
**کد HTML/اسکریپت تبلیغ** هستند که مالک از Option Tree می‌چسباند؛ `esc_html()` آن‌ها را
به متن خام تبدیل می‌کرد و تبلیغ ناپدید می‌شد. تنها راه درستِ همان مورد، فیلتر
`wp_kses_post` یا محدودکردن capability است که در چک‌لیست آمده.

## ج) محافظت لایۀ UI — گارد، نه بریدن فایل

**خواسته:** «CSS لایۀ اختصاصی از style.css جدا شود تا آپدیت قالب مادر آن را نبرد.»

**چرا بریدن فیزیکی انجام نشد:** `style.css` هم محتوای قالب مادر است و هم لایۀ ما؛ اگر
فایلِ بریده‌شده را آپلود کنید و `css/ab-ui.css` جا بیفتد (یا برعکس)، سایت **کاملاً بدون
استایل** می‌شود. در روش دستیِ شما (آپلود از FTP/پیشخوان) این پرریسک‌ترین حالت ممکن است.

**چکار کردیم:**
* `javanseda/css/ab-ui.css` = **کپی** ناحیۀ «`ab-ui-layer` تا انتهای `style.css`»
  (بلوک‌های v3.2.0 → v3.3.8؛ ۴۷KB، بدون تغییر در `style.css` ⇒ در حالت عادی اصلاً
  بارگذاری نمی‌شود، صفر بایت اضافه).
* یک خط مارکر در `style.css` اضافه شد: `/* ── ab-ui-layer ─ … */` درست پیش از بلوک ۲۴.
* `javanseda/inc/ab-ui-guard.php` (از `myfunctions.php` با `locate_template()` include
  می‌شود): وضعیت «مارکر در style.css هست یا نه» را در یک **ترنزینت ۱۲ ساعته** می‌گذارد
  و **فقط اگر مارکر نبود** `css/ab-ui.css` را enqueue می‌کند ⇒ اگر روزی آپدیت قالب مادر
  استایل‌های اختصاصی را پاک کرد، قالب خودش را زنده می‌کند.
* کش با `after_switch_theme` / `upgrader_process_complete` پاک می‌شود و با
  `?ab_uiguard=1` (فقط برای مدیر) دستی قابل تازه‌کردن است.
* `tools/ab-ui-sync.py`: هر وقت بلوک تازه‌ای به `style.css` اضافه کردید، کپی را
  هم‌زمان می‌سازد (`python3 tools/ab-ui-sync.py`).
* `docs/CHILD-THEME.md` هم اضافه شد: راهنمای ساخت child theme اگر بخواهید برای همیشه
  از دست این مشکل راحت شوید (تمیزترین راه، و تنها راهی که آپدیت مادر برایش بی‌خطر است).

خاموشی کل گارد: `define( 'JAVANSEDA_UI_GUARD', false );`

اگر بعداً خواستید بریدن واقعی را انجام دهیم: دو فایل را **با هم** آپلود کنید؛ گارد چون
بر پایهٔ «نبودن مارکر» است، خودبه‌خود همه‌چیز را درست نگه می‌دارد.
