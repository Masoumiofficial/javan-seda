# جوان‌صدا ۳.۵.۴ — گزارش تغییرات

> **در یک خط:** دیدگاه‌ها حالا صفحه‌بندی می‌شوند (پیش‌فرض ۲۰ در هر صفحه) با ناوبریِ
> شماره‌دار، «قدیمی‌تر/جدیدتر»، شمارشِ فارسی و سرتیتر — دیگر با زیادشدنِ کامنت‌ها صفحه
> بی‌نهایت بلند نمی‌شود.

مبنا: ۳.۵.۳ · حذف‌شده: **هیچ** · تغییرِ دیتابیس: **هیچ**

---

## ۱) مسئله

در ۳.۵.۳ (و قبل‌تر) دو چیز باعث می‌شد صفحهٔ نوشته با هر کامنت بلندتر شود:

1. وردپرس به‌طور پیش‌فرض صفحه‌بندیِ دیدگاه را **خاموش** دارد (`page_comments = 0`)، پس
   همهٔ دیدگاه‌ها در یک صفحه چاپ می‌شدند.
2. قالب هم فقط دو لینکِ سادهٔ «قبلی/بعدی» داشت که با خاموش‌بودنِ گزینهٔ بالا هیچ‌وقت
   دیده نمی‌شد و شمارهٔ صفحه/شمارش هم نداشت.

## ۲) راه‌حل

صفحه‌بندیِ **استانداردِ خودِ وردپرس** روی نمای سایت روشن می‌شود؛ نه اختراعِ دوباره:
همان مکانیزمِ `cpage`، `comment-page-N`، پیوند یکتا و شمارشِ هسته. بعد روی آن، یک
ناوبریِ تمیز و یک سرتیتر ساخته می‌شود.

| بخش | جزئیات |
|---|---|
| سرتیتر | «دیدگاه‌ها (۱۲۳)» بالای فهرست |
| خلاصه | «نمایش دیدگاه‌های ۲۱ تا ۴۰ از ۱۲۳ — صفحهٔ ۲ از ۷» |
| ناوبری | شمارهٔ صفحه‌ها با `aria-current="page"`، «قدیمی‌تر/جدیدتر» با `rel="prev"/"next"`، سه‌نقطه برای صفحه‌های دور |
| جای ناوبری | بالا **و** پایینِ فهرست (با ۱۰۰ کامنت لازم نیست تا آخر اسکرول کنید) |
| اعداد | همه فارسی (۱۲۳ / صفحهٔ ۲ از ۷) و بدون جداکننده برای شمارهٔ صفحه |
| انکر | همهٔ لینک‌ها با `#comments` باز می‌شوند (می‌رسید مستقیم به بخش دیدگاه‌ها) |
| بدون JS | کاملاً کار می‌کند؛ هیچ محتوایی حذف یا بازسازی نمی‌شود |
| موبایل | دکمه‌ها کوچک‌تر و بدون سرریز؛ عمقِ تودرتوییِ پاسخ‌ها در ≤۶۰۰px یک پله می‌شود تا عرض کم نشود |
| حالت شب | رنگ‌ها از توکن‌های خودِ قالب (`--ab-*`) |
| دسترس‌پذیری | `nav` با `aria-label`، `aria-current`، فوکوسِ قابل‌دیدن، `prefers-reduced-motion` |

## ۳) کجا کنترلش کنم؟

**پیشخوان → نمایش → تنظیمات قالب → تب «کنترل رابط»** (بالای بخش «عناصر اضافهٔ صفحه»):

| گزینه | کلید | پیش‌فرض |
|---|---|---|
| **صفحه‌بندی دیدگاه‌ها** (روشن/خاموش) | `ab_comments_paging` | روشن |
| **تعداد دیدگاه در هر صفحه** (۵ تا ۱۰۰) | `ab_comments_per_page` | ۲۰ |

نکته‌های مهم:

- تنظیمات وردپرس (**تنظیمات → گفتگو**) **دست‌نخورده** می‌ماند؛ این دو گزینه فقط در نمای
  سایت اثر دارند. (اگر افزونه‌ای `page_comments` را عمداً خاموش نگه می‌داشت، همین لایه
  روی سایت آن را روشن می‌کند.)
- در **پیشخوان، آجاکس و REST** هیچ‌چیز عوض نمی‌شود؛ به همین دلیل صفحهٔ تنظیماتِ گفتگو
  همیشه مقدارِ واقعیِ دیتابیس را نشان می‌دهد.
- خاموش‌کردنِ کامل بدون تغییر کد:
  ```php
  add_filter( 'javanseda_comment_paging', '__return_false' );
  ```
  یا در `wp-config.php`:
  ```php
  define( 'JAVANSEDA_COMMENT_PAGING', false );
  ```
- تغییرِ تعداد در کد:
  ```php
  add_filter( 'javanseda_comments_per_page', function () { return 30; } );
  ```

## ۴) فایل‌ها

| فایل | وضعیت | کار |
|---|---|---|
| `inc/ab-comments.php` | **تازه** | گزینه‌ها، فیلترهای صفحه‌بندی، آمار، خلاصه، سرتیتر و ناوبری |
| `comments.php` | تغییر | سرتیتر + ناوبری بالا/پایین؛ مسیرِ قبلی برای نصبِ نیمه‌کاره حفظ شد |
| `inc/theme-options.php` | تغییر | دو گزینهٔ تازه در تب «کنترل رابط» |
| `myfunctions.php` | تغییر | `require` لایهٔ تازه |
| `css/ab-352.css` | تغییر | بلوک استایلِ ناوبری/سرتیتر/موبایل/شب |
| `style.css` | تغییر | فقط `Version: 3.5.4` |
| `inc/ab-sidebars.php` | تغییر | فقط جدول هشِ عیب‌یابی (ابزار خودِ قالب) |

## ۵) دو باگِ کوچک که در همین مسیر رفع شد

1. **مسیرِ پشتیبانِ دیدگاه‌ها** (وقتی کوئریِ اصلی خالی است) از پارامترِ `page` در
   `get_comments()` استفاده می‌کرد؛ `WP_Comment_Query` چنین پارامتری ندارد. حالا با
   `number` + `offset` دقیقاً همان بازهٔ صفحهٔ جاری خوانده می‌شود.
2. **ناوبریِ قدیمی** فقط وقتی دیده می‌شد که `page_comments` روشن باشد؛ یعنی در عمل هیچ‌وقت.
   حالا ناوبری مستقل از آن گزینه و بر اساس آمارِ واقعیِ همان نوشته ساخته می‌شود.

## ۶) سازگاری و بازگشت

- بدون مهاجرت دیتابیس، بدون تغییر کلید متا، بدون تغییر نامک/پوشه/text-domain.
- اگر `inc/ab-comments.php` روی سرور نبود، `comments.php` دقیقاً مارکاپ قبلی را چاپ
  می‌کند (همه‌چیز با `function_exists` محافظت شده است).
- بازگشت: همان ۷ فایلِ drop-in را از ۳.۵.۳ برگردانید.
