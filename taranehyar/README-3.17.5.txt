تاریخ: 2026-10-15
موضوع: کشِ صفحهٔ خانه — ۹ برابر سریع‌تر روی سایت‌های بزرگ

----------------------------------------------------------------
۱) چه چیزی پیدا شد؟
----------------------------------------------------------------
کاوشگرِ تشخیص روی ahangban.ir این‌ها را نشان داد:

    بوتِ وردپرس          : ۶۴۳ms   ✓ سالم
    رندرِ مستقیم index  : ۲۱۰ms   ✓ سالم (۸۹KB)
    تعداد آهنگ          : ۶۰۶۷
    تعداد جدول          : ۱۱۰

یعنی قالب و وردپرس سالم‌اند. ولی صفحهٔ خانه روی سایتِ واقعی
از **هر بخش** یک کوئری تازه می‌زد و هیچ‌کدام کش نمی‌شدند.

اندازه‌گیری روی ۶۰۰۱ آهنگ (شبیه‌سازی همان حجم):

    بار اول    : ۴۰۵ms با ۸۸ کوئری
    بار دوم    : ۴۴ms  با  ۰ کوئری
    بار سوم    : ۴۳ms  با  ۰ کوئری

کندترین کوئری‌ها:

    ۳۲ms  postmeta JOIN (دو meta_query)
    ۲۸ms  همان
    ۲۵ms  options autoload (۳۱ کوئری option)
    ۱۸ms  SQL_CALC_FOUND_ROWS روی posts

----------------------------------------------------------------
۲) چه کاری کردیم؟
----------------------------------------------------------------
الف) کشِ ۱۰ دقیقه‌ای برای tara_home_query()
     پنج بخشِ خانه (انتشارها، موزیک‌ویدیو، آلبوم، حال‌وهوا، اخبار)
     هر کدام یک WP_Query می‌زدند. حالا نتیجه در transient می‌مانَد.

ب) کشِ ۱۰ دقیقه‌ای برای tara_latest_releases_ids()
     این تابع برای هر کلیدِ تاریخ (۳ کلید) یک get_posts با
     meta_key + orderby=meta_value می‌زد. آن ترکیب باید کلِ
     postmeta را JOIN و مرتب کند. گران‌ترین چیزِ صفحه بود.

ج) پاک‌کنندهٔ خودکار کش
     روی save_post / deleted_post / trashed_post / edited_term
     کش پاک می‌شود. آهنگ تازه بلافاصله در خانه دیده می‌شود؛
     منتظر ۱۰ دقیقه نمی‌مانید.

د) نتیجهٔ خالی هم کش می‌شود
     اگر بخشی داده ندارد، هر بازدید دوباره کوئری نمی‌زند.

هـ) برای کاربرِ واردشده کش نمی‌شود
     تا پیش‌نمایش و ویرایش درست کار کند.

----------------------------------------------------------------
۳) راهِ تنظیم
----------------------------------------------------------------
اگر می‌خواهید کش خاموش/بلندتر شود، در wp-config.php:

    define( 'TARA_HOME_CACHE_TTL', 0 );      // خاموش
    define( 'TARA_HOME_CACHE_TTL', 1800 );   // ۳۰ دقیقه

(از فیلترهای tara_home_query_ttl و tara_latest_releases_ttl هم
می‌شود استفاده کرد.)

----------------------------------------------------------------
۴) اگر باز هم صفحه باز نشد
----------------------------------------------------------------
سه کاوشگر در پوشهٔ tools/diagnostics هست. هر سه را در ریشهٔ
سایت بگذارید و **با مرورگر** باز کنید (نه curl):

    tara-lock-probe.php?key=taranehyar&mode=a
        مسیر واقعی؛ هر هوک با زمان چاپ می‌شود.
        اگر وسطِ کار ایستاد، آخرین خط مقصر است.

    tara-lock-probe.php?key=taranehyar&mode=b
        options autoload، transient، postmeta، cron های سررسیده،
        ایندکس‌های جدول.

    tara-diag.php
        کاوشگرِ سلامت (بدون وابستگی به بوتِ کاملِ وردپرس).

نکته: اگر روی سایت شما ۱۸ افزونه فعال است، ممکن است کندی از
یکی از آن‌ها باشد، نه از قالب. کاوشگر mode=a این را نشان می‌دهد.

پس از تشخیص، فایل‌ها را پاک کنید.
