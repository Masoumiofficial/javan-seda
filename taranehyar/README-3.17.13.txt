ترانه‌یار — نسخهٔ ۳.۱۷.۱۳
================================================================================
موضوع: رفعِ کاملِ خرابیِ سایت هنگامِ فعال‌سازی افزونهٔ ACF Pro


۱) دقیقاً چه اتفاقی می‌افتاد؟
--------------------------------------------------------------------------------

با فعال‌کردن «زمینه‌های سفارشی پیشرفته نسخهٔ حرفه‌ای (ACF Pro)»، سایت
سفید می‌شد یا خطای ۵۰۰ می‌داد.

ریشه در فایل inc/acf-compat.php بود. در نسخهٔ ۳.۱۷.۶ برای جلوگیری از
تضادِ نامِ توابع، این فایل وقتی ACF را فعال می‌دید، با دستور `return`
کلِ فایل را رد می‌کرد:

    if ( defined('ACF_VERSION') || class_exists('ACF') ) {
        return;          // ← کل فایل رد می‌شود
    }

مشکل: تابع‌های اختصاصیِ خودِ قالب — tara_get_field / tara_the_field /
tara_have_rows / tara_get_sub_field — هم پایینِ همان فایل تعریف شده
بودند. با آن `return`، این‌ها **اصلاً تعریف نمی‌شدند**.

در همان حال، ۲۴ نقطه از قالب این توابع را بدون هیچ محافظی صدا می‌زند:

    single.php:178                tara_have_rows( 'album' )
    single.php:183                tara_get_sub_field( 'albumlink320' )
    inc/ab-post-extras.php:216    tara_get_sub_field( $key )
    inc/ab-post-extras.php:263    tara_have_rows( 'album', $post_id )
    inc/tara-ui.php:151           tara_get_field( $key, $post_id )
    inc/ab-seo.php:133            tara_get_field( 'artist', $post_id )
    ... و ۱۸ مورد دیگر

نتیجه:

    Fatal error: Call to undefined function tara_get_field()

یعنی وقتی ACF فعال می‌شد، هر صفحه‌ای که به یکی از این‌ها می‌رسید
وسط کار می‌مرد. چون header.php و سربرگِ همهٔ صفحات از این توابع
استفاده می‌کنند، عملاً تمام سایت سفید می‌شد.


۲) چه چیزهایی اصلاح شد؟
--------------------------------------------------------------------------------

الف) پوستهٔ توابع همیشه تعریف می‌شود
   دستور `return` زودهنگام حذف شد و جایش یک پرچم آمد:

       $tara_acf_native = defined('ACF_VERSION') || class_exists('ACF');

   حالا فقط «بدنهٔ درونیِ جایگزین» (که با wp_postmeta کار می‌کند) پشتِ
   این پرچم می‌ماند و در صورت وجود ACF تعریف نمی‌شود. اما پوستهٔ
   tara_get_field() و ۹ تابع همراه همیشه تعریف می‌شوند و در صورت وجود
   ACF، کار را به خودِ ACF واگذار می‌کنند و در غیر این صورت از
   wp_postmeta می‌خوانند.

   یعنی ۲۴ فراخوانیِ بی‌گاردِ قالب دیگر هرگز به «undefined function»
   نمی‌خورند — چه ACF نصب باشد چه نباشد.

ب) شیءِ ترم دیگر مستقیم به ACF داده نمی‌شود
   در inc/ab-artist-fields.php این کد بود:

       $acf = tara_get_field( $key, $term );     // $term یک WP_Term است

   امضای رسمی ACF:

       get_field( string $selector, int|string $post_id = false )

   ACF نسخه‌های قدیمی این را بی‌صدا رد می‌کردند. ACF Pro 6.x نوع را
   بررسی می‌کند و خطای کشنده می‌دهد:

       TypeError: get_field(): Argument #2 ($post_id) must be of
       type int|string, WP_Term given

   و چون این تابع در سربرگِ هر صفحهٔ هنرمند/ژانر/حال‌وهوا اجرا می‌شود،
   با ACF Pro آن صفحه‌ها خطا می‌دادند.

   اکنون یک تابع تبدیل اضافه شده — tara_get_field_normalize_id() — که
   پیش از رسیدن مقدار به ACF، شیء را به شکلِ درست تبدیل می‌کند:

       WP_Term  →  "{taxonomy}_{term_id}"    مثلاً  tara_mood_72
       WP_User  →  "user_{ID}"               مثلاً  user_1
       WP_Post  →  شناسهٔ عددی
       عدد/رشته →  بدون تغییر

   همین تبدیل در خودِ tara_get_field() هم اعمال می‌شود؛ پس هر جای دیگری
   از قالب که شیء بفرستد هم بی‌خطر است (artist-template.php:113 و
   inc/tara-account-ui.php:835 هم از این مسیر رد می‌شوند).

   برای سازگاری با ACF ۵.۴ و قدیمی‌تر، شکلِ قدیمیِ «term_<id>» هم به‌عنوان
   تلاشِ دوم امتحان می‌شود.


۳) چطور مطمئن شویم؟
--------------------------------------------------------------------------------

همراهِ این نسخه یک فایل عیب‌یاب هست: tools/diagnostics/tara-acf-probe.php

۱. فایل را در ریشهٔ سایت آپلود کنید (کنار wp-config.php).
۲. آدرس زیر را در مرورگر باز کنید:

       https://دامنه‌ی‌شما/tara-acf-probe.php?key=taranehyar

۳. خروجی می‌گوید ACF نصب است یا نه، چه نسخه‌ای، چه چیزی با قالب
   تضاد دارد، و کدام فیلدها داده دارند.

این فایل هیچ چیزی را تغییر نمی‌دهد. بعد از بررسی پاکش کنید
(یا اصلاً آپلود نکنید — لازم نیست).


۴) نتیجهٔ تست
--------------------------------------------------------------------------------

محیط تست: WordPress با PHP 8.4 و یک ACF قلابی که *دقیقاً* مثل ACF Pro 6.x
با type declaration رفتار می‌کند.

   حالت                    صفحهٔ اصلی    ترم حال‌وهوا    ترم هنرمند
   ACF فعال                 ۱۵۱KB ✓       ۱۵۱KB ✓        ۱۵۱KB ✓
   ACF غیرفعال              ۱۵۱KB ✓       ۱۵۱KB ✓        ۱۵۱KB ✓

بدون این اصلاح، در حالت «ACF فعال» خروجی صفر بایت بود
(Fatal error: Call to undefined function tara_get_field).


۵) فایل‌های تغییر‌یافته
--------------------------------------------------------------------------------

   inc/acf-compat.php          بازنویسیِ گارد + تابع تبدیل شیء
   inc/ab-artist-fields.php    استفاده از شکلِ رشته‌ای برای ترم
   style.css                   شمارهٔ نسخه → 3.17.13
   functions.php               شمارهٔ نسخه → 3.17.13

بقیهٔ قالب دست‌نخورده است. هیچ تغییری در ظاهر، چیدمان، رنگ یا رفتار
محتوایی داده نشده — فقط علتِ خرابی برداشته شده.


۶) اگر هنوز مشکل داشت
--------------------------------------------------------------------------------

اگر با این نسخه هم سایت سفید شد، متنِ دقیقِ خطا را بفرستید. در
wp-config.php این دو خط را موقتاً اضافه کنید تا خطا نمایش داده شود:

    define( 'WP_DEBUG', true );
    define( 'WP_DEBUG_DISPLAY', true );
    @ini_set( 'display_errors', 1 );

سپس صفحه را دوباره باز کنید و متنِ «Fatal error» را کامل کپی کنید.
تنها راهِ تشخیصِ قطعی، همان متن است.
